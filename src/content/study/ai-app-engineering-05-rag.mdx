**本篇目标：**从“上传文档就能问”进阶到结果可追溯、质量可评估、权限可控、资料可更新。

**建库链：**文档 → 解析 → 清洗 → 切块 → 元数据 → Embedding → 索引。\
**问答链：**提问 →（按需改写）→ 检索 →（按需重排）→ 上下文 → LLM → 引用与评估。

## 01 / 先建立检索基础

### RAG-01｜适用性判断 · P0 / L2

比较 RAG、微调和普通数据库查询。**验收：**面对一个需求，判断是否真的需要 RAG，并说明数据更新、确定性和成本方面的理由。

### RAG-02｜多格式文档解析 · P0 / L2

考虑 PDF、DOCX、Markdown、HTML、表格和扫描件 OCR 的局限。**验收：**导入至少 3 种格式，保留标题、页码、来源和表格基本结构。

### RAG-03｜清洗、元数据与来源 · P0 / L2

处理页眉页脚、重复、标题层级、来源和权限标签。**验收：**任一检索片段能追溯到具体文件及页码/章节。

### RAG-04｜Chunking 文本切块 · P0 / L2

理解固定长度、重叠、按标题/语义分块的取舍。**验收：**同一批文档比较至少两种策略，并记录检索差异。

### RAG-05｜Embedding 与索引 · P0 / L2

理解向量化、维度、相似度和模型版本一致性。**验收：**建立索引并查询相似文本；更换 Embedding 模型时正确重建索引。

### RAG-06｜向量库 · P0 / L2

从 Chroma、FAISS、Qdrant 或 pgvector 中选择一种。**验收：**独立完成增删查改与元数据过滤，并说明选择理由。

## 02 / 提升检索与回答质量

### RAG-07｜稀疏与混合检索 · P1 / L2

理解 BM25、向量检索、召回率和结果融合。**验收：**用人名、术语或编号查询对比关键词检索与语义检索。

### RAG-08｜Rerank 重排序 · P1 / L2

理解初始召回和精排序的分工，以及延迟/成本。**验收：**在同一测试集上说明加入 Rerank 后效果是提升还是下降。

### RAG-09｜Query 改写 · P1 / L2

处理查询澄清、扩展、拆解和多轮历史。**验收：**为模糊问题设计检索策略，避免改写时凭空补充事实。

### RAG-10｜上下文、引用与拒答 · P0 / L2

掌握片段选择、截断、来源引用和拒答条件。**验收：**每个事实性答案有可核查来源；没有证据时明确说不知道。

## 03 / 评估、安全与运维

### RAG-11｜RAG 评估 · P0 / L3

理解 Recall@K、命中率、答案正确性、忠实度和延迟。**验收：**自建至少 30 组“问题—证据—参考答案”，形成可复现报告。

### RAG-12｜错误归因 · P1 / L3

区分解析、漏召回、排序不准和生成失真。**验收：**分析至少 5 条错误问答，针对原因改进并回归验证。

### RAG-13｜更新与删除 · P1 / L2

理解内容哈希、版本、增量重建和失效清理。**验收：**更新/删除源文件后，旧知识不再被检索。

### RAG-14｜权限过滤 · P0 / L2

理解部门权限、租户隔离和先授权后检索。**验收：**测试 A 部门用户无法检索 B 部门私有片段，服务端过滤先于召回。

### RAG-15｜注入与泄露防护 · P1 / L2

检索内容本身是不可信数据，必须与系统指令隔离。**验收：**恶意文档要求忽略规则、导出密钥时系统不执行。

### RAG-16｜性能与成本 · P1 / L2

关注 Top-K、模型耗时、检索耗时和批量索引。**验收：**显示关键步骤耗时与成本，对比至少两种配置。

## 04 / 通关作品

### 私有知识问答系统

交付文档上传、解析、切块、入库、更新和删除；至少支持 3 种格式；具备向量库元数据过滤、30 组评测、引用与拒答、5 个错误分析和一个权限隔离测试。不要把“回答通顺”当作 RAG 成功。
