**本篇目标：**把 LLM 接入真实业务系统，并让过程可控、可测试、可恢复。模型提出工具调用，服务端验证权限和参数后才真正执行。

## 01 / Agent 工作流核心

### AGENT-01｜Workflow vs Agent · P0 / L2

理解固定流程、动态决策、自主性与风险。**验收：**为 3 个业务需求选择 Workflow 或 Agent，并说明确定性和风险权衡。

### AGENT-02｜Tool / Function Calling · P0 / L2

理解工具定义、参数 Schema、模型建议与程序执行的区别。**验收：**完成模型选择工具 → 后端校验 → 执行 → 返回结果的闭环。

### AGENT-03｜工具设计 · P0 / L2

掌握单一职责、输入输出契约、错误码和权限。**验收：**封装 SQL 查询、知识检索和报告生成三个独立工具。

### AGENT-04｜多步执行循环 · P0 / L2

理解工具循环、最大步数和停止条件。**验收：**模型连续调用至少两个工具，超过步数能够安全终止而非死循环。

### AGENT-05｜状态管理 · P1 / L2

管理任务状态、上下文、短期记忆和持久化。**验收：**程序重启后仍能恢复任务到哪一步，并说明哪些状态应持久化。

### AGENT-06｜分支、重试与补偿 · P1 / L2

处理节点失败、超时、有限重试和重复副作用。**验收：**故意制造 API 故障，任务可恢复或进入安全失败状态。

### AGENT-07｜人工审核 · P0 / L2

为高风险动作加入审批和二次确认。**验收：**发送邮件或更新数据库前必须获得明确授权，未批准时可证明没有副作用。

## 02 / 框架与扩展

### AGENT-08｜LangGraph · P1 / L2

理解 State、Node、Edge、条件分支和持久化。**验收：**实现检索 → 分析 → 审核 → 报告的有状态流程。

### AGENT-09｜Dify Workflow · P1 / L2

理解节点连接、变量映射、错误处理和 API 发布。**验收：**用可视化节点重做同类流程，并解释与代码实现的取舍。

### AGENT-10｜MCP · P2 / L1→L2

掌握 Tool、Resource、Prompt 的基本定位及客户端/服务器边界。**验收：**接入一个可信 MCP 服务，并说明其与普通 API 的异同。

### AGENT-11｜多 Agent 协作 · P2 / L1

理解任务分解、角色边界、协调成本和失败传播。**验收：**针对一个任务说明为何单 Agent 已足够，避免为炫技拆分。

### AGENT-12｜测试与执行追踪 · P1 / L2

记录工具调用轨迹、成功率、成本和失败归因。**验收：**保存至少 20 次任务轨迹，统计成功率和失败分类。

### AGENT-13｜Prompt Injection 防护 · P0 / L2

工具返回内容不可信，权限由后端执行。**验收：**恶意网页不能诱导模型越权发邮件或导出内部数据。

### AGENT-14｜计划任务与通知 · P1 / L2

理解定时触发、任务幂等、告警和通知。**验收：**定时运行分析，失败能告警且不会重复发送报告。

## 03 / 框架选择建议

### Dify + LangChain + LangGraph（按需）

先用 Dify 看清全链路，再用 LangChain 写代码版以弄清原理；只有流程出现复杂状态需求时，才深入 LangGraph。FastGPT 可作为对照体验，不要求两个低代码平台都精通。模型 SDK 应统一认证、重试、切换和输出解析接口。

## 04 / 通关作品

### 行业情报工作流

定时采集 → SQL 查询历史数据 → RAG 检索内部资料 → LLM 摘要 → 人工审核 → 发送报告。未授权前绝不发送。交付工具契约、故障恢复演示和执行轨迹。
