> **适用岗位：**企业知识库（RAG）、Agent 工作流、数据采集与处理、AI 工具研究与落地。本文是为对应 JD 设计的自测路线，不是企业官方考核标准。

这套路线面向已有基础编程经验、希望从“会用 AI”进阶到“能交付 AI 应用”的开发者。按依赖关系学习；每个知识点完成后，留下代码、测试、运行记录、解释或文档等证据，再标记完成。

## 01 / 使用规则与能力等级

### L0｜未接触

不知道知识解决什么问题，或只能照抄示例；换一个案例就无法继续。

### L1｜理解

能不用术语堆砌解释用途、流程和限制，并能修改现有示例。

### L2｜独立应用

不依赖逐步教程，从空项目完成可运行方案，覆盖正常流程和常见异常；有代码、测试或演示证据。

### L3｜工程掌握

能选择方案、说明权衡、定位故障、验证质量并交付可维护版本；有指标、日志、测试、边界说明和复盘。

**升级规则：**L2 至少在一个新题目上独立完成；L3 必须展示异常案例、可复现评估及修复过程。没有证据的等级先记为 L1；没有实践过的项目记为“待测”。

## 02 / 优先级、目标与记录模板

### P0｜必备

JD 明确要求或构成端到端项目的核心。投递前尽量达到 L2。

### P1｜重要

决定项目质量与面试深度。重点模块在自己的项目中达到 L2，部分冲刺 L3。

### P2｜进阶

先能解释概念和适用场景，有余力再做独立项目。

## 03 / 依赖路线与通关作品

### 阶段 A｜Python 与数据底座

完成 Python、合规采集、SQL 和数据清洗。证据：可运行的数据管线、数据库初始化脚本、日志及自动化测试。

### 阶段 B｜LLM 基础

完成模型调用、结构化输出、Prompt 评估和安全意识。证据：结构化抽取 API 与至少 20 条测试样例。

### 阶段 C｜RAG 知识库

完成文档处理、检索、引用、评估和权限隔离。证据：至少 30 组评测问答和质量报告。

### 阶段 D｜Agent 工作流

完成工具调用、状态、失败恢复和人工审批。证据：有执行轨迹的安全工作流。

### 阶段 E｜工程交付

完成 API、部署、安全、监控与业务评估。证据：陌生人能按 README 部署和复现演示。

> 时间没有硬性日历要求。若已熟悉某项基础，可通过自测跳过；学习完成标准始终是交付物，而不是学了几天。

## 04 / 关键误区与使用边界

### 不用“看过”代替“会做”

会刷 Python 算法题不代表会组织工程代码；会聊天式使用 Agent 产品不代表会设计工具调用；Demo 跑通一次也不等于系统可靠。

### 先做最小闭环

不要同时追逐很多框架。先交付“数据采集 → 可信知识检索 → 安全工作流 → 可运行服务”，有测量到的需求再引入新组件。

### 明确安全边界

只采集允许访问的数据；不绕过验证码、付费墙或权限保护。密钥不入库、不写日志。权限必须由服务端校验，不能交给 Prompt。

## 05 / 综合毕业项目与评估入口

毕业项目是一个行业情报与企业知识助手：采集公开新闻，结合模拟或授权的内部资料，提供有引用的问答和每日简报；发送邮件等外部动作必须经过明确审批。

### 项目里程碑

1. **M1 数据管线：**增量采集、清洗、校验、SQL 入库；重跑不重复，中断能恢复。
2. **M2 RAG 核心：**文档导入、索引、问答 API；30 个问题有检索记录、来源引用和拒答案例。
3. **M3 Agent 工作流：**至少两次工具调用；错误可控，外部动作需批准。
4. **M4 工程部署：**FastAPI、Docker Compose、README、最小权限和测试。
5. **M5 工程评估：**至少 5 个错误归因、一次改进前后对照、权限隔离测试。

### 毕业检查与闭卷自测

完成后应能讲清业务价值、数据流、部署方式、问答评测、常见错误、安全边界，并能用 3 分钟演示、10 分钟解释技术选择。

闭卷回答至少 10/12 题并能在代码或测试中指出证据：API 超时与副作用重试；静态采集与动态页面判断；增量去重；Schema 校验；BM25 与向量检索；RAG 故障归因；删除后旧向量清理；如何证明检索提升；Tool Calling 的执行者；Workflow 与 Agent 的选择；Prompt 与服务端授权的差异；如何衡量简报节省的人工时间。

### 100 分能力自评

按 `当前等级 ÷ 3 × 权重` 换算：Python 工程化 15、采集清洗 SQL 20、LLM API/Prompt 10、RAG 25、Agent/Workflow 15、部署安全运维 10、业务交付 5。L3 必须有排错、质量评测或工程权衡证据。

- **低于 40：**知识较零散，先做单模块任务。
- **40–59：**已有基础，需要完整项目暴露问题。
- **60–74：**可开始投递，同时补齐薄弱项。
- **75–89：**已有较完整实践证据，可准备深入面试。
- **90–100：**在这份自测体系内较成熟，但不保证录用结果。

无论总分多少，Python 独立开发、采集并写入 SQL、带来源的 RAG、至少一个安全工作流、密钥与权限意识、可复现项目 README 都不能缺席。

## 06 / 五步学习循环

### 定义目标与原理

先说清这个概念解决什么问题、输入输出是什么、不学会会卡在哪里，以及它的主要限制。

### 独立实现与故障演练

离开逐步教程做一个变化后的新例子；主动制造空数据、超时、权限不足、格式错误或重复任务。

### 留下证据并复盘

提交代码、测试报告和简短复盘；根据证据标记 L2/L3。记录失败原因和下一步，不以看完视频作为通关。

## 07 / 推荐技术栈与控制范围

### 先学一套主栈

Python；FastAPI + Pydantic；`httpx`/Beautiful Soup，确有需要再学 Scrapy 与 Playwright；Pandas + PostgreSQL；pgvector 或 Qdrant；模型 SDK + 结构化输出；LangChain，出现复杂状态再学 LangGraph；Dify 做低代码对照；Docker Compose + Linux。

### 暂缓高成本复杂度

不要一开始部署 Kubernetes、同时学四种向量库、所有网站都用浏览器爬取，或为了炫技引入多 Agent。先测量问题，再引入能带来实际收益的技术。

## 08 / 后续篇章
