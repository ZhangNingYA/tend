**本篇目标：**让别人能通过接口稳定使用你的工具，而不是“只在我的电脑上能跑”。

## 01 / 服务与接口

### ENG-01｜FastAPI · P0 / L2

理解路由、请求/响应模型、依赖注入和异常处理。**验收：**实现文件上传、检索问答、任务状态三类 API。

### ENG-02｜REST 与接口契约 · P1 / L2

理解 HTTP 方法、状态码、幂等、分页和版本。**验收：**生成 API 文档，其他开发者可据此完成集成。

### ENG-05｜数据库连接与迁移 · P1 / L2

掌握连接池、迁移、备份和恢复基本概念。**验收：**服务重启后数据仍在，并从备份恢复测试库。

## 02 / 部署与安全

### ENG-03｜Docker / Compose · P0 / L2

理解镜像、容器、卷、网络和环境配置。**验收：**一条 `docker compose up` 启动 API、数据库和工作流服务。

### ENG-04｜Linux 与 Git · P0 / L2

掌握 Shell、日志、权限、进程、分支和提交。**验收：**能在 Linux 服务器部署并复现故障，Git 历史可审阅。

### ENG-06｜配置与密钥管理 · P0 / L2

理解 `.env`、最小权限和敏感信息处理。**验收：**仓库及日志无真实 API Key，密钥轮换不需要修改程序代码。

### ENG-07｜认证与授权 · P1 / L2

理解用户身份、RBAC 和服务端权限校验。**验收：**两个权限不同的用户访问到的数据不同，未授权请求被拒绝。

## 03 / 可靠性与运维

### ENG-08｜Redis / 后台任务 · P1 / L1→L2

理解缓存、任务队列和消息幂等。**验收：**长耗时任务异步执行，用户能查询状态且重试不重复提交副作用。

### ENG-09｜监控与日志 · P1 / L2

掌握结构化日志、请求 ID、错误率和延迟。**验收：**根据一次失败请求 ID 定位出错节点。

### ENG-10｜测试与 CI · P1 / L1→L2

理解单元、集成、端到端和自动检查。**验收：**每次提交自动运行关键测试，失败会阻止合并。

### ENG-11｜成本与并发 · P1 / L2

关注 LLM 成本、限流、缓存和并发任务。**验收：**模拟多请求，识别瓶颈并采取限流或缓存措施。

### ENG-12｜灾难与边界 · P1 / L2

处理文件大小、超时、恶意上传和回滚。**验收：**超大文件及错误格式不会拖垮服务，并能说明拒绝策略。

## 04 / 通关作品

### 可复现的服务交付

交付带 API 文档、Docker Compose、最小权限配置、测试、结构化日志和部署 README 的系统。让一位未参与开发的人按文档完成部署和演示。
