**本篇目标：**能与非技术人员讨论需求，并证明 AI 确实改善流程，而不只是增加一个看起来聪明的 Demo。

## 01 / 需求到方案

### BIZ-01｜业务流程拆解 · P0 / L2

识别输入、处理、审批、输出、角色和边界。**验收：**把一句模糊需求拆为可验证的 SOP 流程图。

### BIZ-02｜需求澄清 · P0 / L2

明确现状痛点、用户群、数据来源、约束和验收条件。**验收：**输出一页需求说明，定义“成功”是什么。

### BIZ-03｜自动化选型 · P0 / L2

理解规则代码、数据库查询、RAG、LLM、Agent 的适用范围。**验收：**对一个流程标出哪些步骤不应交给 LLM，并解释理由。

## 02 / 评估与协作

### BIZ-04｜Prompt 模板库 · P1 / L2

管理模板、版本、测试集、变更说明和回滚。**验收：**每个 Prompt 有用途、输入、输出、示例和版本记录。

### BIZ-05｜KPI 与收益评估 · P1 / L2

衡量完成时间、错误率、人工审核率、成本和可靠性。**验收：**对照人工基线计算节省时间与新增代价。

### BIZ-06｜AI 工具评测 · P1 / L2

比较安全、价格、集成、质量和维护成本。**验收：**对比 2–3 个备选工具，形成有结论的决策表。

### BIZ-07｜文档与演示 · P1 / L2

编写 README、部署手册、系统图和故障说明。**验收：**陌生同学按文档完成安装并复现演示用例。

## 03 / 综合毕业项目

### 行业情报与企业知识助手

场景：跟踪一个行业的公开新闻，结合模拟或授权的内部手册/流程文档，生成有依据的每日简报并回答问题。输入包含公开网页/API、授权文档和自然语言问题；不能抓取未授权内容，不能跨权限检索，邮件等外部动作要审批。

建议架构：公开源 → Python 采集 → 清洗/校验 → PostgreSQL；企业文档 → 解析/切块 → Embedding → 向量库；用户问题 → FastAPI → RAG/SQL 工具 → LLM/Agent → 带引用回答 → 人工审核后分发。

### 12 项验收场景

用固定数据逐一验证：文档明确答案；同义问题；编号检索；无证据拒答；新旧文档冲突；删除后旧片段不命中；部门权限隔离；提示注入防护；SQL/API 异常；重复触发幂等；未审批不发送；可观测检索耗时、模型耗时和用量。

### 最终交付与面试说明

交付物应包括可运行项目、README、部署说明、系统图、测试、至少 30 条 RAG 评测问答、5 个失败归因、改进前后对照、权限测试、成本与延迟报告。面试时能解释问题价值、数据流、技术选择、主要限制与下一步。

## 04 / 投递前复核

### 六项必备证据

- 能用 Python 独立开发和调试完整程序，而非只复制示例。
- 能使用至少一种爬虫方案，并将清洗数据写入 SQL 数据库。
- 能用 RAG 回答问题、引用来源并检查检索质量。
- 能实现至少一条完整的 LLM 工具调用/工作流。
- 能解释数据安全、密钥保护和用户权限边界。
- 能展示可运行项目及可复现 README。

硬性项达到 L2、核心模块有一个完整项目即可开始投递，不必等所有 P1/P2 学完；本路线的自评分数不保证企业录用结果。
